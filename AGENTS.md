# Development conventions

Use npm and strict TypeScript for the Obsidian plugin. Keep discovery independent from exports and UI. Never infer download permission from playback access. Add tenant adapters only against documented API contracts or anonymised, verified examples. Keep fictional fixtures clearly distinguished from real Panopto schemas. No passwords, cookies, tokens or signed URLs in logs, persisted state, fixtures or manifests. Do not introduce broad mandatory website access.

Run `npm run test:all` for functional changes. Test the built Obsidian plugin, exercise learning pages in Chromium, and inspect actual V2 downloads. Keep failure tests; never weaken assertions to conceal implementation failures. Add regression coverage for new adapters and caption formats. Use Prettier. Keep limitations and real-session verification requirements current in docs. Never claim tenant compatibility based solely on local mocks.

The user has explicitly requested a network-playback export mode. Keep it behind the deliberate Find playback streams action; do not infer export permission for other resources or automatically enable it during normal discovery. The current supported assembly contract is the unencrypted MPEG-TS VOD subset of RFC 8216. Reject encrypted media and unsupported layouts, never fetch decryption keys, and retain source URLs only in bounded ephemeral memory. Regression tests must decode actual assembled audiovisual output, in addition to checking manifests.

Explicit user-authorised exception (2 November 2026): authenticated browser session cookies/tokens may be stored locally in an OS-backed keychain for the opt-in Remember login feature. Save the post-load session so iframe/SSO cookies are included. Never put these secrets in vault files, plaintext storage, logs, fixtures or manifests; refuse plaintext keyring backends. Tests must use fake keychain storage.
