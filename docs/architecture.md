# Architecture

WXT builds MV3 background, all-frame content script, popup and export page. React shares the interface between popup and the durable export manager. The service worker initializes storage; content scripts answer discovery messages using the current DOM. The export page re-discovers resources from the source tab. There is no hosted service, cookie API access, request modification or main-world script injection. Read-only network URL observation supports the explicit playback action.

`src/discovery/session.ts` recognizes Viewer/Embed URLs and extracts metadata. `resources.ts` independently normalizes downloadable links, playback media/captions and chapter-track notices. `index.ts` composes them. Generic links classify video, audio, captions, slides/presentations and attachments by extension; unknown types remain attachments. Future tenant adapters should return the same Resource contract without modifying the downloader.

`src/captions.ts` handles timed SRT/VTT. `src/export.ts` owns selection, stable indexed paths, filenames, sequential downloads, conversion, outcomes, manifests and zip.js sinks. Sequential work limits network pressure. Folder media uses Chrome's native downloader, waits for terminal completion and avoids JavaScript buffering. Caption conversion uses bounded buffers. ZIP streams response bodies into a writable file when the save picker is supported; fallback uses a Blob archive. Original captions remain even if conversion fails; this is explicitly marked partial.

`src/App.tsx` owns ephemeral selection, resource state and user actions. Storage retains only a last-job summary, never session URLs. A manager closed midway cannot resume automatically; rediscover and retry. Resource success indicates the sink accepted bytes and, for folder exports, Chrome completed the download. HTTP errors and sign-in HTML are rejected by fetch-based exports; native folder media relies on Chrome's terminal download state and cannot detect a successful HTML sign-in response.

Permissions: activeTab and scripting for user-granted custom sites, downloads for folder output, storage for job summaries. Mandatory hosts cover Panopto-owned domains and localhost simulation. Optional HTTPS hosts are requested one origin at a time. Embedded frames are supported where content scripts have host permission; open the viewer directly if the Moodle wrapper prevents detection.

When a tab-wide discovery request yields no session, the scanner injects the content script into accessible frames and sends a separate discovery request to each returned frame ID. Non-lecture wrappers cannot mask the embedded viewer's response in this fallback. Access grants from the manager target its recorded source tab rather than the active manager tab itself.

Network export: `src/network.ts` normalises candidate URLs without embedding them in display names. The worker keeps a bounded, ephemeral per-tab list, and the content script can return standard resource-timing entries. The explicit playback button promotes supported candidates to selections on the user's request; encryption and layout checks occur before HLS data export. `src/hls.ts` fetches a complete playlist, rejects unsupported/encrypted layouts and emits sequential MPEG-TS segments with backpressure. Streaming ZIP consumes this stream directly. Buffered sinks cap assembled media at 128 MiB. Direct network media uses the existing downloader unchanged. `webRequest` adds read-only URL observation under already-granted host permissions; optional CDN grants remain per-origin.

The playback action supplements URLs with loaded browser caption snapshots from `src/browser-captions.ts`. Direct audio and VTT/SRT URLs are classified by `src/network.ts`. `src/renditions.ts` fetches up to eight bounded (2 MiB) playlists with a timeout and exposes standard EXT-X-MEDIA renditions. If separate tracks are present, the parent master is not offered as a complete export; individual audio/video playlists are offered instead. Subtitle playlists are reported unsupported until WebVTT timestamp-map assembly exists. Discovery failures retain the original candidate so optional CDN access can be granted before retrying.
